# Database Structure

This document describes the Google Sheets structure used as the central database for the maintenance inventory system.

## Overview

The system uses a single Google Sheets workbook with multiple tabs.

Each tab stores a specific type of information and is connected to AppSheet through relationships and references.

The main tables are:

```text
Items mantenimiento
Movimientos Mantenimiento
Detalle Movimientos Mantenimiento
Solicitud de mantenimiento
Facturas mantenimiento
Tarjetas Mantenimiento
Departamentos
Personal
Unidades
```

## Main Database Relationships

```text
Items mantenimiento
        |
        v
Movimientos Mantenimiento
        |
        v

        |
        v
Stock Calculation

Departamentos ----+
                  |
Personal ---------+----> Origin / Destination
                  |
Unidades ---------+

Facturas mantenimiento
        |
        v
Movimientos Mantenimiento
```

## Items mantenimiento

This table contains the master catalog of products registered in the system.

It can include:

* Tools.
* Equipment.
* Consumables.
* Parts.
* Spare parts.

Main fields include:

| Field                  | Description                                         |
| ---------------------- | --------------------------------------------------- |
| Item ID                | Unique identifier of the product.                   |
| Product Name           | Name of the tool, equipment, part, or consumable.   |
| Description            | General product description.                        |
| Image                  | Product reference image.                            |
| Serial Number          | Manufacturer serial number, when available.         |
| Asset Type             | Fixed asset or consumable.                          |
| Registration Date      | Date when the product was registered.               |
| Registration Signature | Signature associated with the product registration. |

The `Item ID` is used as the main reference for identifying products in other tables.

## Movimientos Mantenimiento

This table stores the general information for each inventory transaction.

Only one row is created per movement, even when multiple products are included.

Main fields include:

| Field                 | Description                                           |
| --------------------- | ----------------------------------------------------- |
| Movement ID           | Unique identifier of the transaction.                 |
| Date and Time         | Timestamp of the movement.                            |
| Movement Type         | Entry, exit, or loan.                                 |
| Origin                | Department, unit, or employee providing the products. |
| Destination           | Department, unit, or employee receiving the products. |
| Reason                | Reason for the movement.                              |
| Observations          | Additional transaction information.                   |
| Invoice or Ticket     | Supporting document, when applicable.                 |
| Delivery Responsible  | Person responsible for delivering the products.       |
| Receiving Responsible | Person responsible for receiving the products.        |
| Receiving Email       | Email address used for notifications.                 |
| Evidence              | Supporting image or document.                         |
| Delivery Signature    | Signature of the person delivering the products.      |
| Receiving Signature   | Signature of the person receiving the products.       |

The `Movement ID` is used to associate the main transaction with its product-level detail records.

## Detalle Movimientos Mantenimiento

This table contains the inventory impact generated by each movement.

Unlike the main movement table, this table stores records individually by product and location.

For each product included in a movement, two records are generated:

```text
Origin      | Negative Quantity
Destination | Positive Quantity
```

Example:

```text
Movement ID: MOV-00125
Product: Hydraulic Tool
Quantity: 2

MOV-00125 | Maintenance Department | Hydraulic Tool | -2
MOV-00125 | Unit 03                | Hydraulic Tool | +2
```

Main fields can include:

| Field       | Description                                               |
| ----------- | --------------------------------------------------------- |
| Detail ID   | Unique identifier of the detail record.                   |
| Movement ID | Reference to the parent movement.                         |
| Item ID     | Reference to the product.                                 |
| Location    | Department, unit, or employee associated with the record. |
| Quantity    | Positive or negative inventory quantity.                  |
| Date        | Date associated with the movement.                        |

This table is the primary source used to calculate the current stock.

## Solicitud de mantenimiento

This table stores maintenance requests submitted to the department.

It provides a centralized list of maintenance requirements that can be consulted and managed from the application.

Depending on the operational process, requests may contain information such as:

* Request ID.
* Request date.
* Requesting department.
* Responsible person.
* Description of the maintenance requirement.
* Status.
* Observations.

## Facturas mantenimiento

This table stores maintenance-related invoices and supporting purchase documents.

It can be used to maintain references to documents associated with:

* Product purchases.
* Spare parts.
* Consumables.
* Maintenance services.
* Inventory entries.

These records can be referenced from inventory movements when required.

## Tarjetas Mantenimiento

This table stores maintenance cards or records used by the department.

Its purpose is to centralize maintenance-related documentation that can be referenced from AppSheet.

The exact fields depend on the operational maintenance process.

## Departamentos

This table contains the list of company departments.

It is used as a reference catalog for inventory assignments and movements.

Example:

```text
Department ID
Department Name
```

Departments can be selected as:

* Origin.
* Destination.
* Current inventory holder.

## Personal

This table contains the company personnel catalog.

It is used to identify employees involved in inventory transactions.

The information can include:

* Employee ID.
* Name.
* Email.
* Department.
* Position.

Personnel records can be referenced as:

* Origin.
* Destination.
* Delivery responsible.
* Receiving responsible.
* Inventory holder.

## Unidades

This table contains the company vehicle or operational unit catalog.

It allows inventory to be assigned directly to specific units.

The information can include:

* Unit ID.
* Unit number.
* Description.
* Type.
* Department.

Units can be selected as:

* Origin.
* Destination.
* Current inventory location.

## Entity Relationships

The primary relationships between tables can be represented as:

```text
                 Items mantenimiento
                         |
                         | Item ID
                         v
               Movement Detail Records
                         ^
                         |
                         | Movement ID
                         |
              Movimientos Mantenimiento
                  /       |       \
                 /        |        \
                v         v         v
         Departamentos  Personal  Unidades
```

Supporting information can also be associated with:

```text
Facturas mantenimiento
Solicitud de mantenimiento
Tarjetas Mantenimiento
```

## Stock Calculation

Current inventory is not stored as a manually editable quantity.

Instead, stock is calculated using all records stored in:

```text
Detalle Movimientos Mantenimiento
```

For each combination of product and location:

```text
Current Stock = Sum of all positive and negative quantities
```

Example:

```text
Maintenance Department | Product A | +10
Maintenance Department | Product A | -3
Maintenance Department | Product A | -2
```

Result:

```text
Maintenance Department | Product A | 5
```

This model preserves historical information and avoids losing previous inventory transactions.

## Database Design Benefits

The database structure provides:

* Centralized information management.
* Product-level traceability.
* Movement-level audit history.
* Separation between transaction headers and product details.
* Inventory calculation based on transaction history.
* References to personnel, departments, and units.
* Integration with AppSheet automations.
* Cloud-based access through Google Sheets.

## Summary

The database follows a transactional structure in which:

```text
Products
   |
   v
Movements
   |
   v
Movement Details
   |
   v
Stock
```

Reference tables such as `Personal`, `Departamentos`, and `Unidades` provide the entities required to identify where inventory is located and who is responsible for each transaction.

This structure allows the system to maintain both the current inventory status and the complete historical record of how each product has moved through the organization.
